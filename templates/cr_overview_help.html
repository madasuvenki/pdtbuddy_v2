What is CR Overview?

CR Age Overview is a cross-BU dashboard for Change Requests (CRs). It gives you a unified view of CR age, status, site distribution, and area breakdown across all Business Units and targets — all in one place.

BU Summary
Per-BU cards showing CR counts by status. Click a BU card to drill into its targets.
Site Distribution
QIPL, SD, CH site cards showing how CRs are distributed across test sites.
Main Chart
CR distribution by your selected dimension (Area, BU, Status, Functionality, Subsystem).
CR Detail Table
Paginated, sortable rows of individual CRs with age, status, site, and JIRA info.
Using the Filters
Filter What it does Tips
Business Unit Narrows all charts, cards and tables to a single BU or shows all BUs together. Select All BUs for a cross-BU view.
Date Range Filters CRs by their JIRA date. Presets: Last 3/6/9/12 months, by year, or custom range. Use All Time (default) to see the full history.
NoSIR Toggles the NoSIR CR category. The badge shows the count of NoSIR CRs. Click once to enter NoSIR mode; click again to exit.
Invalid Toggles the Invalid CR category. The badge shows the count of Invalid CRs. Mutually exclusive with NoSIR mode.
CR Status Multi-select checkbox list. Choose only the statuses you want to see. Use All / None buttons to quickly select or clear all statuses.
View (Dimension) Controls how the main chart and breakdown table group CRs: BU, Area, Functionality, Subsystem, or Status. Switch to Area to see which CR areas have the most open CRs.
Age Unit Switches age display between Days and Weeks across all charts and tables. Use Weeks for long-running programmes to reduce visual noise.
Target Multi-select dropdown to filter to one or more specific targets within the selected BU. Use the search box inside the dropdown to find targets quickly.
All filters work together — changing any filter instantly refreshes every chart, card and table on the page.
Understanding the Charts
  • 1
    Main CR Distribution Chart — Stacked bar chart grouped by your selected dimension. Each bar segment represents a CR status. Click any bar to open the Area → Target drill-down panel below.
  • 2
    CR Age by Status — Shows average CR age per status bucket. Helps identify which statuses have the oldest CRs. The dots below the chart show age count distribution.
  • 3
    Occurrence / Breakdown Table — Pivot table showing CR counts per dimension value and status. Use the Copy Table button to paste into Excel.
  • 4
    Expand button — Each chart has an Expand button that opens a full-page modal with a larger chart and data table. Use Prev / Next to slide between charts.
Click any bar in the main chart to open the Area → Target Breakdown drill-down panel, which shows per-target CR counts and site distribution for that area.
CR Detail Table

The CR Detail table shows individual CR rows with full metadata. It is paginated and sortable.

Sort options
Age (Days/Weeks) high→low or low→high, Site A→Z, JIRA Date new→old, Occurrence high→low, and more.
Rows per page
Choose 40, 100, or 200 rows per page. Click Load Rows after changing settings.
Copy Table
Copies the visible rows as a tab-separated table — paste directly into Excel or Google Sheets.
Status filter
The detail table respects the CR Status checkbox filter above. Change statuses and click Load Rows to refresh.
The detail table does not auto-refresh when you change filters — click Load Rows to apply the latest filter settings.
Drill-down Panels
  • 1
    Area → Target Breakdown — Click any bar in the main chart. A panel appears below showing which targets contribute to that area, with a per-target bar chart and site distribution cards.
  • 2
    Site Detail Panel — Click any site card (QIPL, SD, CH). A panel appears showing site-specific KPIs, a breakdown table, and CR detail rows for that site.
  • 3
    Closing panels — Use the Close or Clear Site button on each panel, or click a different bar/site to switch the drill-down.
Tips & Tricks
  • ★
    Use Expand All / Collapse All buttons in the filter bar to quickly show or hide all page sections.
  • ★
    The Reset button clears all filters back to defaults (All BUs, All Time, All Statuses).
  • ★
    Switch the View dimension to Status to see a status-by-status breakdown in the main chart.
  • ★
    Use the Target multi-select to compare a specific set of targets side-by-side.
  • ★
    The Dive into BUs button on each BU card opens the full BU workspace with per-target dashboards.
  • ★
    Data is cached for ~30 minutes per target. If you need fresh data, ask an admin to clear the cache from the Admin panel.
Troubleshooting
ProblemLikely causeFix
No data / empty charts Filters are too restrictive, or no CRs match the selected date range and status. Click Reset to clear all filters and reload.
Stale data CR data is cached for ~30 minutes. Wait for the cache to expire, or ask an admin to clear it via /admin/cr_overview/clear_cache.
Detail table not updating The detail table requires a manual refresh. Click the Load Rows button after changing filters.
Target missing from dropdown Target may be excluded by an admin, or not yet ingested. Ask an admin to check the Manage Targets panel (gear icon, admin only).
Chart not rendering Highcharts library failed to load. Hard-refresh the page (Ctrl+Shift+R) to reload all scripts.
System Overview

CR Overview reads directly from the PDT Buddy MySQL database — no Excel ingestion needed at query time. The service layer aggregates data from unique_crs and jiras tables across all BU schemas.

The service uses per-target locks to prevent duplicate DB fetches when multiple users load the page simultaneously. Only one DB query runs per target per cache window.

All endpoints require login. The targets param supports multi-target: ?targets=T1,T2,T3 — this overrides the single target param.
Frontend Architecture
cr_overview_v2.js
Main JS module. Manages state, API calls, chart rendering (Highcharts), table rendering, filter wiring, and drill-down panels.
cr_overview_v2.css
All styles for the CR Overview page: hero, filters, BU cards, site cards, charts, tables, drill-down panels, and modals.
Highcharts v12
Used for all bar charts, stacked charts, and the CR Age by Status chart. Loaded locally with CDN fallback.
State object
A single state object tracks current filters, loaded data, active drill-down, pagination, and chart instances.

The page uses a single-page pattern: all filter changes trigger a new API call to /api/cr_overview, and the response is used to re-render all sections without a full page reload.

Cache Strategy
  • 1
    Per-filter cache key — Each unique combination of (bu, target, dim, status_filter, site, date_from, date_to, flt_*) gets its own cache entry.
  • 2
    30-minute TTL — Cache entries expire after 30 minutes. The next request after expiry triggers a fresh DB query.
  • 3
    Per-target locks — A threading lock per target prevents duplicate DB queries when multiple users request the same target simultaneously.
  • 4
    Manual bust — Admins can call POST /admin/cr_overview/clear_cache to evict all entries immediately. This also happens automatically when excluded targets are saved.
  • 5
    Warmup — On server start, warmup_cache() pre-populates the cache for all active targets so the first user request is fast.
