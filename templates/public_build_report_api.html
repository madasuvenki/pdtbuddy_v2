🔌 Build Report API

PDTBuddy Share consolidated build reports with external tools

Overview

The Build Report API exposes the same consolidated report engine used by the Build Report standalone page as a machine-callable REST API. Pass a JIRA filter ID or JQL — get the full report JSON back immediately. No job_id, no polling.

✅ One call, one response. Pass your filter ID → get the report. Works with a browser session (internal users) or an API token (external tools).
🔑 What is the token? It's a long random string set in the server's .env file as PDTBUDDY_API_TOKEN=your-secret-here. The admin generates it once and shares it with teams who need API access. Verify yours: curl -H "X-PDTBuddy-API-Token: TOKEN" http://<host>/api/token/verify

Authentication

🔑 API Token (required for external tools)

Send your token in one of these ways:

MethodExample
HTTP Header (recommended)X-PDTBuddy-API-Token: your-token-here
Authorization BearerAuthorization: Bearer your-token-here
Query parameter?api_token=your-token-here

The token is configured by the admin via the PDTBUDDY_API_TOKEN environment variable (or JIRAQUERY_API_TOKEN as an alias). Verify your token: 

curl -H "X-PDTBuddy-API-Token: YOUR_TOKEN" http://<host>/api/token/verify

Browser sessions (logged-in users) are also accepted — no token needed from the UI.

⭐ Primary Endpoint — Synchronous (Recommended)

Pass a filter ID or JQL, get the full report back in one call. Same output as the Build Report page.

POST /api/build_report/run Run report synchronously — same as the Build Report page ▼

Runs the consolidated report and returns the full JSON immediately. No job_id, no polling.

Request Body (JSON) or GET params

FieldTypeRequiredDescription
filter_idstringrequired*JIRA saved filter ID (e.g. "76997") or full filter URL
custom_jqlstringrequired*Direct JIRA JQL string
buildsstringrequired*Comma-separated build IDs
targetstringoptionalTarget name for context (e.g. "ALDABRA")
traversebooleanoptionalFollow linked JIRAs (default: true)
orbitbooleanoptionalEnrich with Orbit CR data (default: true)

* At least one of filter_id, custom_jql, or builds is required.

Response (200)

{
  "ok": true,
  "filter_id": "76997",
  "meta": { "jql": "...", "build_ids": [...] },
  "summary": { "total_jiras": 42, "with_cr": 28 },
  "hierarchical_report": [ /* CR-grouped JIRA rows */ ],
  "jiras": [ /* flat list of all matched JIRAs */ ],
  "cr_index": { /* CR details keyed by CR number */ }
}

Examples

# Pass a JIRA saved filter ID — same as selecting it in the Build Report page
curl -s -X POST http://<host>/api/build_report/run \
  -H "Content-Type: application/json" \
  -H "X-PDTBuddy-API-Token: YOUR_TOKEN" \
  -d '{"filter_id": "76997"}'
# Pass direct JQL
curl -s -X POST http://<host>/api/build_report/run \
  -H "Content-Type: application/json" \
  -H "X-PDTBuddy-API-Token: YOUR_TOKEN" \
  -d '{"custom_jql": "project = QSTABILITY AND summary ~ \"SecaAU_IVI.LE.1.0-00070\""}'
import requests

HOST  = "http://<host>"
TOKEN = "YOUR_TOKEN"

# One call — full report returned immediately
resp = requests.post(
    f"{HOST}/api/build_report/run",
    json={"filter_id": "76997"},
    headers={"X-PDTBuddy-API-Token": TOKEN},
)
report = resp.json()
print(report["summary"])          # {"total_jiras": 42, "with_cr": 28, ...}
print(len(report["jiras"]))       # 42
# Logged-in users can call from the browser console (no token needed)
const resp = await fetch('/api/build_report/run', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ filter_id: '76997' })
});
const report = await resp.json();
console.log(report.summary);

Advanced: Async Endpoints (for long-running reports)

For very large reports that may time out, use the async job pattern. The page itself uses this internally.

POST /api/consolidated_report Start a background Build Report job (async) ▼

Starts an async consolidated report job. Returns a job_id immediately.

Request Body (JSON)

FieldTypeRequiredDescription
buildsstring or arrayrequired*Build ID(s). Comma-separated string or JSON array. e.g. "SecaAU_IVI.LE.1.0-00070"
custom_jqlstringrequired*Direct JIRA JQL or saved filter ID/URL. Required if builds not provided.
targetstringoptionalTarget name for context (e.g. "ALDABRA")
traversebooleanoptionalFollow linked JIRAs (default: true)
orbitbooleanoptionalEnrich with Orbit CR data (default: true)
forcebooleanoptionalBypass cache and re-run (default: false)
cache_ttl_minutesnumberoptionalCache TTL in minutes (default: 30)
include_axiom_metricsbooleanoptionalInclude Axiom stability metrics (default: false)

* Either builds or custom_jql is required.

Response

{
  "ok": true,
  "job_id": "3f8a1c2d-..."
}

HTTP 202 Accepted. Use job_id to poll for results.

Examples

curl -s -X POST http://<host>/api/consolidated_report \
  -H "Content-Type: application/json" \
  -H "X-PDTBuddy-API-Token: YOUR_TOKEN" \
  -d '{"builds": "SecaAU_IVI.LE.1.0-00070", "target": "ALDABRA"}'
import requests, time

HOST = "http://<host>"
TOKEN = "YOUR_TOKEN"
HEADERS = {"X-PDTBuddy-API-Token": TOKEN}

# 1. Start job
r = requests.post(
    f"{HOST}/api/consolidated_report",
    json={"builds": "SecaAU_IVI.LE.1.0-00070", "target": "ALDABRA"},
    headers=HEADERS,
)
job_id = r.json()["job_id"]

# 2. Poll for result
while True:
    res = requests.get(f"{HOST}/api/consolidated_report/result/{job_id}", headers=HEADERS)
    if res.status_code != 202:
        report = res.json()
        break
    time.sleep(3)

print(report["summary"])
# PowerShell
$headers = @{ "X-PDTBuddy-API-Token" = "YOUR_TOKEN"; "Content-Type" = "application/json" }
$body = '{"builds": "SecaAU_IVI.LE.1.0-00070", "target": "ALDABRA"}'
$r = Invoke-RestMethod -Uri "http://<host>/api/consolidated_report" -Method POST -Headers $headers -Body $body
$jobId = $r.job_id

# Poll
do {
    Start-Sleep 3
    $res = Invoke-WebRequest -Uri "http://<host>/api/consolidated_report/result/$jobId" -Headers $headers
} while ($res.StatusCode -eq 202)
$report = $res.Content | ConvertFrom-Json
$report.summary
GET /api/consolidated_report/result/<job_id> Fetch completed report by job ID ▼

Returns the completed report JSON. Non-destructive — safe to call multiple times.

StatusMeaning
202 + {"status":"pending"}Job still running — poll again
200 + report JSONReport complete
500 + {"error":"..."}Job failed

Report JSON Structure

{
  "meta": {
    "build_ids": ["SecaAU_IVI.LE.1.0-00070"],
    "target_name": "ALDABRA",
    "generated_at": "2026-08-05T10:30:00",
    "jql": "summary ~ \"SecaAU_IVI.LE.1.0-00070\" AND filter = 76997 ..."
  },
  "summary": {
    "total_jiras": 42,
    "with_cr": 28,
    "open_jiras": 15
  },
  "hierarchical_report": [ /* CR-grouped JIRA rows */ ],
  "jiras": [ /* flat list of all matched JIRAs */ ],
  "cr_index": { /* CR details keyed by CR number */ }
}

Example

curl -H "X-PDTBuddy-API-Token: YOUR_TOKEN" \
  http://<host>/api/consolidated_report/result/3f8a1c2d-...
GET /api/consolidated_report/progress/<job_id> SSE stream of job progress events ▼

Server-Sent Events (SSE) stream. Emits JSON progress events until the job completes. Useful for real-time progress bars. For simple polling, use the /result endpoint instead. 

# Each SSE event looks like:
data: {"stage":"running","done":12,"total":50,"pct":24,"message":"Fetching JIRA tickets..."}

data: {"stage":"done","done":50,"total":50,"pct":100,"message":"Report complete."}

Example (curl)

curl -N -H "X-PDTBuddy-API-Token: YOUR_TOKEN" \
  http://<host>/api/consolidated_report/progress/3f8a1c2d-...
GET /api/consolidated_report/status Preflight check — verify JIRA credentials are configured ▼

Returns whether JIRA credentials are configured on the server. Use this as a health check before submitting jobs.

{
  "ok": true,
  "configured": true,
  "jira_user_set": true,
  "jira_password_set": true,
  "jira_server": "https://jira-dc2.qualcomm.com/jira/",
  "message": "JIRA credentials configured."
}
curl -H "X-PDTBuddy-API-Token: YOUR_TOKEN" http://<host>/api/consolidated_report/status
GET /api/consolidated_report/load Load a previously cached report from disk ▼

Returns a previously saved report without re-running JIRA/Orbit queries.

ParamTypeDescription
buildsstringComma-separated build IDs
targetstringTarget name (optional)
{
  "found": true,
  "report": { /* full report JSON */ },
  "saved_at": "2026-08-05T10:30:00"
}
curl -H "X-PDTBuddy-API-Token: YOUR_TOKEN" \
  "http://<host>/api/consolidated_report/load?builds=SecaAU_IVI.LE.1.0-00070&target=ALDABRA"

Also Available: Synchronous Raw API

The /api/jiraquery/raw endpoint runs the report synchronously (blocks until complete). Suitable for small builds or scripted one-shot calls. Uses the same PDTBUDDY_API_TOKEN.
GET POST /api/jiraquery/raw Synchronous consolidated report (blocks until done) ▼
ParamTypeDescription
buildsstringComma-separated build IDs
targetstringTarget name (optional)
projectstringJIRA project keys e.g. QSTABILITY,CHIPMD
filter_idstringJIRA saved filter ID (overrides default)
traverseboolFollow linked JIRAs (default: true)
raw_onlyboolReturn flat JIRA list only (default: false)
curl -H "X-PDTBuddy-API-Token: YOUR_TOKEN" \
  "http://<host>/api/jiraquery/raw?builds=SecaAU_IVI.LE.1.0-00070&target=ALDABRA"

Environment Setup

⚙️ Admin: Configure API Token

Add to your .env file and restart PDTBuddy:

# .env
PDTBUDDY_API_TOKEN=your-long-random-token-here

# Generate a secure token (PowerShell):
[System.Web.Security.Membership]::GeneratePassword(40, 5)

# Generate a secure token (Python):
python -c "import secrets; print(secrets.token_urlsafe(40))"
