What is PDT Buddy?

PDT Buddy is a cross-BU engineering dashboard for Change Requests, JIRAs, MTBF, build reports, live status, and weekly/monthly analytics. It aggregates data from PDT Stats, Orbit, JIRA, and Axiom into a single unified view.

CR Overview
Cross-BU CR age, status, site distribution and area breakdown. Click bars to drill down into targets.
Target Dashboard
Per-target MTBF, CR age, open/mapped CRs, JIRA counts, and build health in one view.
Live Status
Real-time running builds, device counts, Axiom hours, and published public-token status reports.
Weekly Reports
Weekly CR age, CR TAT, unique CR report, farm testing, and smart build report using Axiom jobs.
Build Report
Live JQL by build ID, JIRA→CR traversal, mapped CR and open JIRA tables with serial/MCN columns.
PDT Buddy AI
Ask the chatbot about any CR, status, build, or JIRA. Auto-loads CR info panel when a CR number is detected.

Navigating PDT Buddy
  • 1
    Left sidebar — Lists all BUs and targets. Click a BU to expand its targets. Click a target to open its full dashboard.
  • 2
    Top bar — BU / Target selector — Quick-jump to any target dashboard directly from the top bar. Select BU → Target → click Go.
  • 3
    Target Delta — Opens the Target Delta Studio to compare two targets side-by-side.
  • 4
    Publish Report / View — Publish a live status report or view previously published reports and join groups.
  • 5
    PDT Buddy AI (robot icon) — Opens the AI chatbot. Ask about any CR number, status, build, or JIRA. The CR Info tab auto-loads when a CR is detected.

Copy Table

Drill-down panels
Click a chart bar → Area→Target panel. Click a site card → Site Detail panel with per-site KPIs and rows.
The detail table does not auto-refresh when filters change — click Load Rows to apply the latest filter settings.
Tips & Tricks
  • ★
    Use Expand All / Collapse All in the filter bar to quickly show or hide all page sections.
  • ★
    The Reset button clears all filters back to defaults (All BUs, All Time, All Statuses).
  • ★
    Switch the View dimension to Status to see a status-by-status breakdown in the main chart.
  • ★
    Use the Target multi-select to compare a specific set of targets side-by-side.
  • ★
    Data is cached for ~30 minutes per target. If you need fresh data, ask an admin to clear the cache.
  • ★
    Hard-refresh (Ctrl+Shift+R) if charts are not rendering — this reloads all scripts including Highcharts.

Frontend Stack
Highcharts v12
All bar charts, stacked charts, MTBF trend charts. Loaded locally with CDN fallback.
Vanilla JS modules
Each page has its own JS module (e.g. cr_overview_v2.js). No framework — pure DOM + fetch API.
CSS per page
Each major page has its own CSS file. Global styles in base.css and style.css.
Flask + Jinja2
Python Flask backend with Jinja2 templates. MySQL via SQLAlchemy. Login via Flask-Login.

Open Ticket Form
What to Include in Your Ticket
  • 1
    Summary — One-line description of the issue or request. Be specific: e.g. "CR Overview — MOBILE BU site cards show 0 for SD site".
  • 2
    Steps to reproduce — Exact steps: which page, which filters, what you clicked, what you expected vs what happened.
  • 3
    Target / BU — Which target or BU is affected. Include the target key if known (e.g. nord_hgy).
  • 4
    Screenshot or URL — Attach a screenshot or paste the full URL from your browser address bar.
  • 5
    Priority — Is this blocking your work (High) or a nice-to-have improvement (Low)?
