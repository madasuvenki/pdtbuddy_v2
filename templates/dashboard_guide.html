All Dashboard Tabs & Features
CR Overview
Cross-BU CR age analysis with site distribution and area breakdown
/cr_overview/embed

The CR Overview is the main landing page after login. It shows a cross-BU view of all Change Request (CR) ages, statuses, and distributions. Use it to quickly identify which BUs or areas have the most aging CRs.

Key KPIs
Total CRs
~1,200
All active CRs across selected BU/targets
Avg Age
~85d
Average CR age in days for open CRs
Sites
3
QIPL, SD, CH site distribution
How to Use
  1. Select a BU from the top filter (or keep All BUs for cross-BU view)
  2. Use the Date Range picker to filter CRs by creation date
  3. Toggle NoSIR / Dup / Invalid chips to include or exclude those CR categories
  4. Click any bar in the chart to drill into area → target breakdown
  5. Use the View selector to switch between BU, Area, Subsystem, Functionality grouping
  6. Click Expand to view the chart full-screen with a data table below
Tip: The CR age bucket table below the chart shows exact counts per age range (0-7d, 7-14d, 14-21d, >21d). Click a bucket to filter the detail rows.
Dashboard Tab
Main PDT execution view — KPIs, CR age charts, area breakdown
/dashboard/<target>/dashboard

The Dashboard tab is the primary view for a specific target. It shows all key PDT execution metrics in one place — JIRA counts, CR age distribution, area breakdown, and site distribution.

KPI Cards (top row)
  • Mapped JIRAsAll JIRAs that have been successfully mapped to a CR. These are tracked and resolved.
  • Open JIRAsJIRAs that are still open and not yet mapped to a CR. Requires action from the PDT team.
  • Closed JIRAsJIRAs that have been resolved/closed. Indicates completed work.
  • Total JIRAsSum of all JIRAs (mapped + open + closed) for the selected target and date range.
  • Total PDT CRsTotal unique CRs reported by PDT. Broken down into Valid, Invalid, and Dup counts.
CR Avg Age Chart
  1. Shows CR average age (in days or weeks) grouped by Area, Subsystem, or Functionality
  2. Use the View selector to switch between Summary, Area, Subsystem, Functionality
  3. Use Age Unit to toggle between Days and Weeks
  4. Click a bar to filter the CR detail table below by that area/subsystem
  5. Use CR Status checkboxes (Analysis / Built / Open / Ready) to filter which CRs appear
  6. Use Detailed Status checkboxes to further filter by sub-status
Analysis/Open CRs by Area (right chart)

Horizontal bar chart showing CR count per area. Toggle between Valid / Invalid / Dup using the radio buttons below the chart. Click a bar to filter the CR table.

The age bucket table at the bottom shows exact CR counts per age range. Use Copy Chart to copy the chart image to clipboard for reports.
Device Summary Tab
Device pool, pass/fail rates, per-device PDT execution status
/dashboard/<target>/device-summary

The Device Summary tab shows the current state of all PDT devices for this target — how many are deployed, which are actively running tests, and the pass/fail breakdown. Data is pulled from Axiom (live) and the Excel device list.

Key Sections
  • Device Pool SummaryTotal devices configured, deployed, and actively running SWPDT or HWPDT. Shows site-wise breakdown (QIPL, SD, CH).
  • SW Delivered / DeployedHow many SW units have been delivered to each site vs. how many are deployed and running tests.
  • HW MetricsHardware device counts by revision (REV0, REV1, etc.) and part type. Shows total HW units in the PDT pool.
  • Device ListFull list of all devices with serial number, MCN, host PC, storage, location, and rework info. Editable by editors.
How to Use
  1. Switch between SWPDT and HWPDT using the PDT type selector
  2. Click Refresh to pull the latest device data from Axiom
  3. Editors can Add / Edit / Delete device rows using the action buttons
  4. Use Remove from Pool to exclude a device from MTBF calculations without deleting it
  5. Click Upload Excel to replace the device list with a new Excel file
Tip: The device pool sync status shows when data was last fetched from Axiom. If stale, click Refresh to get the latest running device counts.
MTBF Tab
MTBF Excel data — trend chart, build-wise hours/crashes/MTBF table
/dashboard/<target>/mtbf-excel

The MTBF tab shows the Mean Time Between Failures trend for this target. Data comes from the configured Excel file and is displayed as a chart and table. Editors can add new builds, edit existing rows, or upload a new Excel file.

MTBF Formula
MTBF = Total Hours / Total Crashes — Higher MTBF means better stability. A build with 1000 hours and 5 crashes has MTBF = 200 hours.
Chart Features
  • MTBF Trend LineShows MTBF value per build over time. Upward trend = improving stability.
  • Hours BarTotal test hours per build. More hours = more test coverage.
  • Crashes LineTotal crash count per build. Lower is better.
How to Use (Editors)
  1. Click Add Build to add a new MTBF data row (Meta-ID, date, hours, crashes)
  2. Click the Edit button on any row to modify existing data
  3. Click Delete to remove a row
  4. Click Upload Excel to replace the entire MTBF dataset with a new file
  5. Use Last N Builds filter to show only the most recent builds in the chart
Note: MTBF data is stored in the Excel file on the shared drive. Changes made here update the file directly. Always verify before saving.
SWPDT Tab
Software PDT MTBF data from Axiom — separate from MTBF Excel tab
/dashboard/<target>/mtbf-table (pdt_type=SWPDT)

The SWPDT tab shows the Software PDT MTBF data fetched directly from Axiom (the PDT job tracking system). Unlike the MTBF Excel tab, this data is automatically synced from Axiom and shows the latest running build statistics.

Key Differences from MTBF Tab
  • Auto-synced from AxiomData is automatically updated from the Axiom job summary database. No manual entry needed.
  • Build-level granularityShows MTBF per individual build ID (e.g. SA8797P.HQX.5.7.7.0-00623) rather than per Meta-ID.
  • Filterable tableSearch by build ID, date, or Meta-ID. Sort by any column. Export to CSV.
How to Use
  1. Use the search box to filter by build ID or Meta-ID
  2. Click column headers to sort by that column
  3. Use Last N Builds to limit the view to recent builds
  4. Click Refresh to pull the latest data from Axiom
SWPDT data is updated every 30 minutes by the Axiom poller. The "Last Updated" timestamp shows when data was last synced.
HWPDT Tab
Hardware PDT data — chip/part counts, tested vs projected, CR overlap
/dashboard/<target>/hwpdt (pdt_type=HWPDT)

The HWPDT tab shows Hardware PDT execution data — how many hardware chips/parts have been tested, what's projected, and how HWPDT CRs overlap with SWPDT CRs. This tab is only visible when HWPDT is configured for the target.

Key Sections
  • Chip/Part SummaryTotal chips tested vs. projected. Breakdown by revision (REV0, REV1, etc.) and part type (PERF, STD, etc.).
  • Tested PartsList of all chip IDs that have been tested in HWPDT. Pulled from Axiom chip ID database.
  • CR Venn DiagramShows overlap between HWPDT CRs and SWPDT CRs — which CRs appear in both, only HWPDT, or only SWPDT.
How to Use
  1. View the chip summary to see tested vs. projected counts per revision
  2. Click Projected Parts to set the expected total chip count for this target
  3. Use the Venn diagram to identify CRs that are unique to HWPDT vs. shared with SWPDT
  4. Click any segment of the Venn diagram to see the CR list for that segment
HWPDT tab is only shown when hwpdt_available = true for this target. Contact admin to enable HWPDT for a target.
Weekly Report Tab
Weekly CR age, CR TAT, unique CRs, farm testing — with PPT download
/dashboard/<target>/weekly-report

The Weekly Report tab shows a comprehensive weekly summary for this target. It covers CR age distribution, CR turnaround time (TAT), unique CR list, and farm testing data from Axiom. The same data is available as a downloadable PPT slide deck.

Report Sections
  • CR Age DistributionHow many CRs fall into each age bucket (0-7d, 7-14d, 14-21d, >21d) for the selected week. Compares to previous week.
  • CR TAT (Turnaround Time)Average time from CR creation to CR resolution (built/closed) for CRs closed during the week.
  • Unique CRsDeduplicated list of all CRs reported during the week, with area, subsystem, status, and JIRA count.
  • Farm TestingAxiom job summary for the week — total jobs, pass/fail counts, hours run, and build-wise breakdown.
How to Use
  1. Select the date range (defaults to last Monday–Sunday)
  2. Click Generate Report to load data for the selected week
  3. Switch between tabs (CR Age, CR TAT, Unique CRs, Farm Testing) to view each section
  4. Click Download PPT to get a PowerPoint slide deck of the weekly summary
  5. Use JIRA Reporter Filter (AUTO targets) to filter by specific reporters
Tip: The PPT download generates a ready-to-present slide deck with all charts and tables. Use it directly in weekly PDT review meetings.
Open_Analysis CR Tab
Detailed analysis of Open and Analysis-status CRs with age distribution
/dashboard/<target>/open-cr-analysis

The Open_Analysis CR tab provides a deep-dive into CRs that are currently in Open or Analysis status. It shows age distribution, area/subsystem breakdown, and a filterable CR table. Use this tab to identify the oldest and most critical open CRs.

Key Features
  • Age Distribution ChartBar chart showing how many CRs fall into each age bucket. Red bars = older CRs that need attention.
  • Area/Subsystem BreakdownPie or bar chart showing CR distribution by area and subsystem. Click a segment to filter the table.
  • Filterable CR TableFull list of open/analysis CRs with CR ID, title, area, subsystem, age, JIRA count, and notes. Sortable and filterable.
How to Use
  1. Use the Status checkboxes to toggle between Open CRs, Analysis CRs, or both
  2. Click a bar in the age chart to filter the table to that age range
  3. Click a segment in the area chart to filter the table to that area
  4. Use the search box in the table to find specific CRs by ID, title, or area
  5. Click Copy Table to copy the filtered CR list to clipboard
CRs in Analysis status are being investigated but not yet fixed. CRs in Open status are confirmed bugs awaiting a fix. Both require active tracking.
PDT CRs Tab
Full PDT CR list — Valid/Invalid/Dup, Analysis/Built/Open/Ready filters
/dashboard/<target>/pdt-crs

The PDT CRs tab shows the complete list of all PDT CRs for this target — both SWPDT and HWPDT. It includes all CR statuses (Valid, Invalid, Dup) and all detailed statuses (Analysis, Built, Open, Ready). Use this tab for comprehensive CR tracking and reporting.

CR Status Categories
  • Valid CRsCRs that are confirmed PDT bugs. Includes Analysis (being investigated), Open (confirmed, awaiting fix), Built (fix integrated), and Ready (fix ready for release).
  • Invalid CRsCRs that were filed but determined to be not a real bug (e.g., user error, environment issue, cannot reproduce).
  • Dup CRsDuplicate CRs that map to an existing CR. The canonical CR is shown in the "Mapped CR" column.
How to Use
  1. Use CR Status checkboxes (Valid / Invalid / Dup) to filter the main category
  2. Use Detailed Status checkboxes (Analysis / Built / Open / Ready) to filter sub-status
  3. Use the search box to find CRs by ID, title, area, or subsystem
  4. Click column headers to sort by CR age, JIRA count, area, etc.
  5. Click Export to Excel to download the filtered CR list as an Excel file
  6. Click any CR ID to open the CR in Orbit (external link)
Tip: Use the PDT Priority column to identify P1/P2 CRs that need immediate attention. Filter by priority to focus on critical issues.
Open JIRAs Tab
Unmapped JIRA tickets — not yet linked to a CR, requires action
/dashboard/<target>/open-jiras

The Open JIRAs tab shows all JIRA stability tickets that have NOT been mapped to a CR yet. These are open bugs that need to be investigated and either linked to an existing CR or used to file a new CR. This is a key action item for the PDT team.

Table Columns
  • JIRA KeyThe stability ticket ID (e.g. QSTABILITY-12345). Click to open in JIRA.
  • JIRA DateWhen the JIRA was filed. Older JIRAs that are still open need priority attention.
  • ReporterWho filed the JIRA. Use the JIRA Reporter Filter (AUTO targets) to filter by specific reporters.
  • Source TableWhich database table this JIRA came from (e.g. openjiras, jiras). Helps identify the data source.
How to Use
  1. Review the list of open JIRAs — these all need CR mapping or investigation
  2. Use the JIRA Reporter Filter (AUTO targets only) to filter by specific reporters
  3. Use the search box to find JIRAs by key, title, or component
  4. Click Export to CSV to download the list for offline analysis
  5. Click any JIRA key to open it in JIRA and start the investigation
Action Required: Open JIRAs represent unresolved stability issues. Each JIRA should be investigated and either mapped to an existing CR or used to file a new CR in Orbit.
Live Status View
META selection, consolidated CRs/JIRAs, ADAS MTBF, current running build report
/live_status_view/AUTO/<target>

The Live Status View is a separate page (not a tab in the main dashboard) that provides a DB-backed META selection interface. Select one or more META builds to get a consolidated view of all CRs and JIRAs for those builds.

Page Sections
  • META SelectionTable of all META builds with hours, crashes, and MTBF. Select one or more META rows and click Submit to get the consolidated report.
  • Consolidated ResultAfter submitting, shows Summary, CRs tab, Open JIRAs tab, and Exclusions tab for the selected META builds.
  • ADAS MTBFView and edit MTBF data per domain (ADAS/FLEX/IVI). Add new builds, edit existing rows, toggle crash type filters.
  • Current ReportLive running build JIRA→CR report. Shows current running builds and their associated CRs/JIRAs in real time.
  • Unique CRs by TargetCross-target unique CR list grouped by domain (FLEX/ADAS/IVI). Shows which CRs appear across multiple targets.
How to Use
  1. Select META rows from the table (use checkboxes) and click Submit Selected
  2. View the Summary tab for KPIs, then switch to CRs or Open JIRAs tabs
  3. Add JIRA/CR IDs to Exclusions to remove them from the consolidated view
  4. Click Save & Refresh to apply exclusions and regenerate the report
  5. Use the ADAS MTBF tab to add/edit MTBF builds per domain
Build Report
Run JIRA JQL by build ID, traverse JIRA→CR mappings, get hierarchical report
/build_report (or via Live Status View)

The Build Report runs a JIRA JQL query for one or more build IDs, traverses the JIRA→CR mapping chain, enriches with Orbit CR data, and returns a hierarchical CR/JIRA report. It's the most powerful tool for understanding what CRs and JIRAs are associated with a specific build.

How It Works
  1. Enter a build ID (e.g. SA8797P.HQX.5.7.7.0-00623) or select from running builds
  2. Select a JIRA filter (saved filter ID) or enter custom JQL
  3. Click Run — the system fetches all matching JIRAs from JIRA server
  4. Each JIRA is traversed through linked tickets to find the final CR
  5. CRs are enriched with Orbit data (title, status, area, SI image, built date)
  6. Results show a hierarchical view: CR → mapped JIRAs → open JIRAs
Report Tabs
  • CRs TabAll CRs found for this build, with title, area, subsystem, status, age, and linked JIRA count. Click a CR to see its JIRAs.
  • Mapped JIRAs TabAll JIRAs that were successfully mapped to a CR through the traversal chain.
  • Open JIRAs TabJIRAs that could not be mapped to any CR. These need investigation.
AI Summary: Click Generate AI Summaries to get one-line AI-generated summaries for each CR using QGenie. Useful for quick review in meetings.
