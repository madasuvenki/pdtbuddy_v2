Add & Ingest New Target

Fill in all required fields. Fields change based on the Business Unit selected.

🔑 Unique CR Only mode: Registers the target with only a unique_cr_path. No Excel ingestion needed. Only BU, Target Key, Display Name and Unique CR Path are required.
Step 1 — Business Unit
ⓘ What is a Business Unit? The BU determines the hierarchy structure:
• AUTO  Automotive — 5-level: Gen → Program → Family → Category → SP
• WBC  Wireless Base Chip — 2-level: Target → SP
• AUTO_TELEMATICS  Auto Telematics — 2-level: Target → SP (same as WBC)
• MOBILE / COMPUTE / XR  Standard — flat target list, no sub-hierarchy
Step 2 — Target Key
⚠ Important: This is the internal DB identifier — used as the database table prefix and URL key.
• Use lowercase_with_underscores only — no spaces or special chars
• Must be unique across all targets — e.g. skyros, molokai_v2, balsam_r2
Step 2 — Mobile Product Family
📱 Mobile grouping: Mobile targets are grouped using product_family.
• VT — default/current Mobile targets
• PT
• PT-AU
💡 Stored as product_family in DB and used by the Mobile target selector dropdown.
Step 2 — Automotive Hierarchy
🚗 AUTO Hierarchy: Generation → Program → Family → [Category → SP Label]
• Gen + Program + Family only → creates the Family Overall Dashboard (the “Open Dashboard” button on the Family pill)
• + Category + SP Label → creates an SP-level card shown when user clicks “Expand SPs”
💡 Stored as platform in DB — groups targets by hardware generation (e.g. Gen5, Gen4.5)
💡 Stored as program in DB — the vehicle program name. Shown as a Program pill in the hierarchy.
💡 Stored as product_family in DB — the chip family. Shown as a Family pill in the hierarchy.
⚠ Category & SP Label are optional:
• Leave Category empty → Family Overall Dashboard (no SP card)
• Fill Category + SP Label → SP-level card shown under “Expand SPs”
💡 Stored as application_domain in DB — the use-case domain (ADAS, IVI, FLEX). Leave empty for family-level overall.
💡 Stored as cpl in DB — the SP version label shown as the bold title on the SP card. NULL = family-level overall.
Pattern: Program or Program_Family e.g. Nord / Nord_HGY  |  With Category+SP: Nord_HGY_ADAS_5_1_7_0
Step 2 — WBC Hierarchy
🔌 WBC Hierarchy: Target → SP Label
• Target = chip/platform name e.g. Kuno, Kobuk, Pinnacles — stored as product_family & program in DB
• SP Label = optional software platform version e.g. LE.1.1 — stored as cpl in DB — blank creates the target-level overall dashboard
💡 Stored as product_family & program in DB — groups all SPs under this Target pill in the hierarchy.
💡 Stored as cpl in DB. Leave blank for the target-level overall dashboard; use dot notation e.g. LE.1.1 for an SP card.
Pattern: Target_SP e.g. kuno_le1_1 — used as DB table prefix & URL key
Step 3 — Target Details (all BUs)
💡 Shown in the dashboard header and target selector. Can contain spaces & mixed case. Stored as target_display in DB.
💡 The physical SoC/chip identifier. Stored as chip_name in DB. Used for display and filtering.
💡 The exact OneView SP identifier used to fetch milestone dates (ES, FC, CS, CS1). Stored as sp_name in DB.
Format: CHIP.Family.Version — e.g. SA8797P_ADAS.HGY.5.1.7.0 or QAM8255.LE1.1
💡 Network path to the Excel file or folder for data ingestion. Stored as excel_path in DB.
💡 Path for Unique CR data. Required in Unique CR Only mode. Stored as unique_cr_path in DB.
